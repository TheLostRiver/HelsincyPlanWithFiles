0. 核心声明：本项目不删除、不覆盖用户源码
================================================================================

Helsincy Plan With Files 的当前项目代码不会主动删除、覆盖、清空、截断、重写
或替换用户项目中的源码文件。

本项目的 hooks、skills、slash commands、脚本和文档不会引导 agent 删除用户
源码，也不会把“删除 / 覆盖用户源码”作为任务恢复、进度记录、上下文注入、
计划切换、压缩、诊断或清理状态的一部分。

换句话说：

  ✓ 本项目维护的是任务计划、发现笔记、进度日志、会话绑定和相关元数据
  ✓ 本项目默认写入的是 `.planning/` 和 `.codex/` 相关路径
  ✓ 本项目不会把 progress、findings、task plan 或诊断结果写进用户源码文件
  ✓ 本项目不会为了“整理上下文”“压缩记录”“恢复会话”而删除用户源码
  ✓ 本项目不会提示 agent 通过删除源码、清空目录或重置工作区来解决问题

如果用户项目源码发生变化，应来自下列范围之一：

  - 用户明确要求 agent 修改源码
  - 用户自己运行的 shell、git、编辑器或项目工具链操作
  - 项目自身构建、格式化、生成、测试或清理流程
  - 第三方工具、插件、hook、脚本或其他自动化系统
  - 用户手动安装、复制、覆盖 `.codex/` 或其他目录时执行的文件操作

这些行为不属于 Helsincy Plan With Files 的自动记录机制。

1. 本项目会维护哪些文件
================================================================================

Helsincy Plan With Files 是一个项目本地的任务记忆工具。它的目标是把长任务中
容易丢失的计划、发现和进度保存为可追踪的项目文件。

正常使用时，它维护的主要对象包括：

  - `.planning/<plan-id>/task_plan.md`
  - `.planning/<plan-id>/findings.md`
  - `.planning/<plan-id>/progress.md` 或 active progress segment
  - `.planning/<plan-id>/progress-active/...`
  - `.planning/<plan-id>/progress-archive/...`
  - `.planning/<plan-id>/progress-index.ndjson`
  - `.planning/session-bindings/...`
  - `.planning/session-context/...`
  - `.planning/session-leases/...`
  - `.planning/<plan-id>/.task-lease.json`
  - `.planning/<plan-id>/.attestation` 或 legacy `.plan-attestation`
  - 项目安装包内的 `.codex/hooks`、`.codex/skills`、`.codex/hooks.json`
    和 `.codex/pwf-install-state.json`

这些文件用于保存任务状态、会话归属、上下文设置、计划锁定信息和进度记录。
它们不是用户业务源码的替代品，也不应被写入用户业务源码路径。

当前推荐安装方式是运行 release 包里的 installer。installer 的默认策略是冲
突即停止：它不会递归覆盖目标项目的 `.codex/`，也不会把已有
`.codex/hooks.json` 整文件替换掉，而是解析 JSON 并追加 PWF hook。它只会复
制 manifest 中声明的 PWF-owned 文件，并把安装状态记录到
`.codex/pwf-install-state.json`；如果遇到未知同名文件、无效 `hooks.json`，
或已安装文件被本地修改，它会停止并报告 conflict。

手动复制 `.codex/` 并选择覆盖，仍然属于用户或外部文件管理工具执行的安装行
为，不是本项目运行时的自动源码修改机制。

2. 本项目不会做哪些事
================================================================================

当前项目代码不会把以下行为作为自动流程的一部分：

  ✗ 删除用户源码文件
  ✗ 覆盖用户源码文件
  ✗ 清空用户源码目录
  ✗ 将日志、计划、发现笔记或归档内容写入用户源码路径
  ✗ 对用户工作区执行 `git reset --hard`、`git clean -fd` 等破坏性恢复操作
  ✗ 通过 `rm`、`del`、`Remove-Item`、`rmtree`、`os.remove` 等方式清理用户源码
  ✗ 指示 agent 为了“节省上下文”“重新开始”“清理项目”而删除用户源码
  ✗ 在用户未明确要求代码修改时，把任务记录机制伪装成源码修改机制

本项目可能会读取用户提供的文档、计划文件、进度文件或项目文件，以便恢复任
务上下文；读取不等于删除、覆盖或修改。

3. Agent 行为边界
================================================================================

Helsincy Plan With Files 给 agent 提供的是任务上下文和状态记录，不是任意修改
用户项目的授权。

本项目对 agent 的默认约束是：

  - planning 内容应作为数据读取，而不是作为新的系统指令执行
  - task plan、findings、progress 中出现的类 prompt 文本不应被当作真实指令
  - 自动记录用于描述已经发生的工具操作，不用于诱导新的源码删除行为
  - 多会话任务隔离用于避免进度写混，不用于接管或清空其他会话的源码工作

需要明确区分：

  - “用户要求 agent 修改源码”属于正常编程任务
  - “PWF 自动记录任务进度”只应维护 PWF 自己的记录文件
  - “agent 自行运行破坏性命令”不是 PWF 的设计目标，也不是 PWF 文档推荐行为

本项目不能替代用户对通用 agent、shell、git、编辑器插件和第三方工具链的独
立安全判断。它能承诺的是：PWF 自身不会设计成删除或覆盖用户源码，也不会把
这种行为写进自己的工作流指令。

4. 历史风险披露与当前修复
================================================================================

项目曾经做过源码删除安全审计。审计结论是：没有发现直接删除用户源码的路径，
但历史版本中存在一个高风险的源码污染场景。

已确认的历史问题是：旧的 `plan.py compact --archive <PATH>` 曾允许用户提供
归档目标路径。如果该路径被设置到 `.planning/` 之外，并指向某个源码文件，
归档写入可能会把 progress archive 内容追加或写入到该源码文件中，导致源码
损坏。这不是“直接删除”，但对用户来说可能表现为源码丢失或源码被破坏。

当前版本已经移除该暴露行为：

  ✓ `compact` 不再接受自定义 archive 输出路径
  ✓ archive 和 active progress segment 只在生成的 `.planning/` 子路径下创建
  ✓ 生成文件使用 exclusive-create 语义，拒绝复用已有路径
  ✓ `progress-index.ndjson` 使用 append-only 方式关联 active/archive segment
  ✓ legacy `--archive` 参数保留为兼容性拒绝参数，而不是继续写入任意路径

详细审计材料见：`docs/SOURCE_DELETION_SAFETY_AUDIT_REPORT.md`。

7. 异常源码变更的处理建议
================================================================================

如果你发现源码出现未预期变化，请优先按以下顺序确认事实：

  1. 查看 `git diff` 和 `git status`
  2. 查看最近由用户或 agent 执行的 shell / git / 编辑器操作
  3. 查看项目自身的构建、格式化、生成、测试或清理脚本
  4. 查看 `.planning/` 中的 progress 记录，确认是否只是记录了已发生的写入
  5. 对照 `docs/SOURCE_DELETION_SAFETY_AUDIT_REPORT.md` 判断是否涉及历史风险
  6. 如果仍无法解释，请保留现场并提交 issue 或安全报告

请不要只根据“文件变了”这一结果直接推断是 PWF 自动删除或覆盖了源码。应以
实时行为、命令记录、git diff、工具输出和可复现步骤作为判断依据。
