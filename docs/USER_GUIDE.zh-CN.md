# Helsincy Plan With Files 普通用户使用指南

这篇文档写给第一次使用的人。它尽量少讲术语，先讲“这个工具能帮你什么”，再讲“你该怎么用”。

如果你已经熟悉 Codex、hooks、session、lease 这些概念，可以直接看 [README](../README.md) 或 [FAQ](FAQ.md)。

## 一句话说明

Helsincy Plan With Files 是给 Codex 用的“任务记忆本”。

你让 Codex 做一个长任务时，它会把任务计划、重要发现和执行进度写进项目里的文件。这样即使聊天上下文变短、会话关掉又重开、或者同一个项目开了多个 Codex 会话，Codex 也更容易知道现在做到哪一步。

## 它适合什么时候用？

适合：

- 你要让 Codex 做一个需要很多步的任务。
- 任务会改多个文件，或者要跑测试。
- 任务今天做不完，明天还要继续。
- Codex 聊天上下文被压缩后，你担心它忘记之前的决定。
- 同一个项目里开了多个 Codex 会话，你不希望 A 会话的进度写到 B 会话里。
- 你想知道 Codex 到底改过哪些文件、做过哪些检查。

不太需要：

- 你只是问一个很短的问题。
- 你只让 Codex 看一眼某段文字，不需要持续跟进。
- 你不需要保存过程，只要一次性答案。

## 它会在项目里保存什么？

安装后，项目里会出现一个 `.planning/` 文件夹。你可以把它理解成 Codex 的工作笔记本。

里面最重要的是三类文件：

```text
task_plan.md   # 任务计划：目标是什么，分几步做，哪一步完成了
findings.md    # 发现笔记：查到了什么，做了什么判断
progress.md    # 进度日志：什么时候做了什么，改了哪些文件
```

你不需要每天手动编辑这些文件。通常是 Codex 在工作时读取和更新它们。你只要知道：以后恢复任务时，Codex 可以靠这些文件找回状态。

## 第一次安装

普通用户推荐下载 release 里的这个包：

```text
HelsincyPlanWithFiles-v0.2.5-codex.zip
```

安装步骤：

1. 打开 GitHub 的 Latest Release 页面。
2. 下载 `HelsincyPlanWithFiles-v0.2.5-codex.zip`。
3. 解压。
4. 把解压出来的 `.codex/` 文件夹复制到你的项目根目录。
5. 重启 Codex。
6. 如果 Codex 提示是否信任 hooks，选择允许或批准。

你的项目大概会变成这样：

```text
your-project/
  .codex/
  你的其他文件...
```

如果你的项目本来就有 `.codex/` 文件夹，不要直接覆盖。先备份，或者让 Codex 帮你合并。

## 安装后先做什么？

第一步运行：

```text
/pwf-doctor
```

它的作用是检查安装是否正常。你可以把它当成“体检”。

如果结果正常，再开始任务：

```text
/pwf-init 我的任务名
```

例如：

```text
/pwf-init 整理产品说明文档
```

然后查看当前状态：

```text
/pwf-status
```

到这里，一个任务就建好了。接下来你可以正常对 Codex 说：

```text
请帮我整理这个项目的使用说明，先读 README 和 docs，然后给我一个修改方案。
```

## 日常最常用的命令

### 检查工具是否正常

```text
/pwf-doctor
```

适合在安装后、命令不显示、或者感觉状态不对时使用。

### 开始一个新任务

```text
/pwf-init 任务名
```

任务名可以写普通中文，不需要很正式。

如果当前 Codex 会话可以识别，`/pwf-init` 默认会绑定当前会话。你不需要手动记 `--bind-session`；同一个项目里开多个会话时，每个会话新建的任务会默认归自己的会话所有。

少数情况下，如果你明确想用旧的 workspace-only 行为，可以让 Codex 使用 `--no-bind-session`。如果你想让任务只属于当前会话、不要更新项目级 active plan，可以使用 `--no-workspace-active`。

例子：

```text
/pwf-init 修复登录页面问题
/pwf-init 写一版用户手册
/pwf-init 准备 0.2.5 发布
```

### 看当前任务状态

```text
/pwf-status
```

它会告诉你当前绑定的是哪个任务、任务文件在哪里、进度是否需要整理。

### 查看当前会话能用哪些任务

```text
/pwf-tasks
```

这个命令适合在你忘记任务名、任务名很长、或者上下文压缩后想确认当前会话能继续哪个任务时使用。

它会列出当前会话可见的任务，并显示短 ID。短 ID 就像任务的临时编号，方便复制。

### 选择一个任务继续

```text
/pwf-use 短ID
```

例如 `/pwf-tasks` 显示：

```text
[a1b2c3] 写一版用户手册
```

你就可以输入：

```text
/pwf-use a1b2c3
```

这样当前会话就会绑定到这个任务。

### 切换任务

```text
/pwf-switch
```

这个命令会显示或切换当前 active plan。普通单会话使用时可以用它；如果同一个项目同时开了多个 Codex 会话，更推荐先用 `/pwf-tasks` 和 `/pwf-use`，因为它们默认只看当前会话可见任务，更不容易选错。

### 压缩很长的进度日志

```text
/pwf-compact
```

长期任务中，`progress.md` 会越来越长。这个命令会把旧记录归档，保留摘要和最近记录，让后续恢复更轻。

## 一个完整例子

假设你想让 Codex 帮你整理一个项目文档。

第一步，检查安装：

```text
/pwf-doctor
```

第二步，创建任务：

```text
/pwf-init 整理项目文档
```

第三步，让 Codex 开始工作：

```text
请先阅读 README 和 docs 目录，总结这个项目现在的文档问题，不要急着改。
```

第四步，让 Codex 记录发现并修改：

```text
把你发现的问题写进 findings.md，然后开始改 README，让普通用户更容易看懂。
```

第五步，查看当前状态：

```text
/pwf-status
```

第六步，如果今天做不完，明天回来后先运行：

```text
/pwf-status
```

然后对 Codex 说：

```text
继续上次的文档整理任务，先读当前计划和进度，再告诉我下一步。
```

## 同一个项目开多个 Codex 会话怎么办？

这是多会话策略特别加强的地方。

假设你在同一个项目里开了两个 Codex 会话：

- 会话 A：在写文档。
- 会话 B：在修 bug。

你不希望会话 B 把进度写进会话 A 的 `progress.md`。现在最简单的做法是：在每个会话里直接运行 `/pwf-init 任务名`。只要当前会话能识别，新任务默认会绑定当前会话。

也就是说：

- 会话 A 运行 `/pwf-init 写文档`，任务默认绑定会话 A。
- 会话 B 运行 `/pwf-init 修 bug`，任务默认绑定会话 B。
- 会话 C、D、E 也是同样逻辑。

`.planning/.active_plan` 仍可能被更新，但 workspace active 是兼容层。多个会话并发时，当前会话自己的绑定优先，所以不会只因为别的会话后来创建了任务，就把你的会话切过去。

如果你是继续已有任务，而不是新建任务，在每个会话里先运行：

```text
/pwf-tasks
```

它默认只显示当前会话可见的任务，不会把其他会话独占的任务直接列出来。

看到你要继续的任务后，复制短 ID：

```text
/pwf-use 短ID
```

如果你确实要接管另一个会话的任务，或者两个会话有意共享同一个任务，不要靠默认命令偷偷切过去。接管或共享仍必须显式告诉 Codex，让它使用对应的显式命令。

普通用户可以这样说：

```text
我要接管另一个会话之前的任务，请先检查风险，再用显式 claim 操作。
```

或者：

```text
这两个会话需要一起写同一个任务，请用显式 share 操作。
```

这样做有点麻烦，但它能避免最糟糕的问题：多个会话互相写乱进度。

## 上下文压缩后怎么继续？

Codex 聊天变长后，系统可能会压缩上下文。压缩后，聊天里早期内容可能不完整。

这时不要急着继续改文件，建议先运行：

```text
/pwf-status
```

如果你不确定当前任务是哪一个，再运行：

```text
/pwf-tasks
```

然后用：

```text
/pwf-use 短ID
```

确认任务后，再对 Codex 说：

```text
先阅读当前 task_plan.md、findings.md 和 progress.md，告诉我现在做到哪一步。
```

## 我需要懂那些高级词吗？

大多数时候不需要。

你可能会在 README 或 FAQ 里看到这些词：

- hook
- session
- lease
- attestation
- context profile
- strict mode

普通用户可以先不用管。日常只要记住：

- `/pwf-doctor`：检查工具。
- `/pwf-init`：开始任务。
- `/pwf-status`：看状态。
- `/pwf-tasks`：列出当前会话能用的任务。
- `/pwf-use`：选择一个任务继续。
- `/pwf-compact`：进度太长时整理一下。

高级词主要是为了处理更复杂的情况，比如多个会话并发、任务锁定、防止计划被意外改动等。

## 常见问题

### 它会替我完成任务吗？

不会。它不是新的 AI，也不会替代 Codex。它只是帮 Codex 保存任务记忆，让 Codex 更容易连续工作。

### 它会把我的项目内容上传到哪里吗？

这个工具本身只是把 planning 文件写在你的项目本地。它不负责上传文件。Codex 自身如何处理上下文，取决于你正在使用的 Codex 环境。

### `.planning/` 要提交到 git 吗？

通常不要。

`.planning/` 里可能有任务进度、临时判断、项目细节，适合留在本地。这个仓库的 `.gitignore` 默认也建议忽略它。

### 我能手动改 planning 文件吗？

可以，但不建议随便改。更推荐让 Codex 更新它们。

如果你确实要手动改，改完后可以让 Codex 重新读取：

```text
请重新阅读当前 task_plan.md、findings.md 和 progress.md，然后继续。
```

### 命令看不到怎么办？

先重启 Codex，再运行或让 Codex 帮你运行：

```powershell
python .codex\skills\planning-with-files\scripts\plan.py doctor
```

如果 doctor 也找不到文件，通常是 `.codex/` 没有复制到项目根目录，或者你当前打开的不是目标项目。

## 推荐记忆法

把它想成一本项目里的工作笔记：

- `task_plan.md` 是待办清单。
- `findings.md` 是调查笔记。
- `progress.md` 是流水账。
- `/pwf-init` 是新开一本任务笔记。
- `/pwf-status` 是翻到当前页。
- `/pwf-tasks` 是看有哪些任务本。
- `/pwf-use` 是选中其中一本继续写。

这就是它最核心的用法。
